# 要求内容

## 概要

MVP実装完了後の申し送り事項5件を解消し、プロダクト品質を安定させる。

## 背景

MVP実装（2026-03-04）の検証エージェント指摘で未対応の項目が5件残っている。コードレビュー修正は6回実施済みだが、設計とコードの矛盾・テスト未作成が残課題。

## 実装対象

### 1. salary の同月重複チェック削除
- PRDのデータモデルでは Salary の sortOrder を「同月内に複数レコードがある場合の副次ソートキー」と定義
- 現在の `salary-actions.ts` は同月の重複を禁止しているため、PRDと矛盾
- 重複チェックを削除し、同月に複数の手取りレコードを登録可能にする

### 2. dashboard.ts の資金繰りロジック改善
- 現在の `buildFundFlow` は全支払いの引き落とし日を `selectedMonth` 基準で計算
- 実際には異なる利用月の支払いが混在するため、各支払いの実際の利用月から引き落とし日を算出すべき
- 同一カードでも利用月が異なれば引き落とし日が異なるケースを正しく処理

### 3. category-form.tsx のカラー Input 確認
- 申し送りでは「カラー Input 二重 register」が指摘されていた
- 現状コードは Controller パターンで実装済み → 確認のみ

### 4. テストファイル作成
- Vitest による単体テストを作成
- 対象: ユーティリティ関数、バリデーションスキーマ

### 5. マイグレーション確認
- `prisma/migrations/` にファイルは存在（0001_init, 0002_add_budget_model）
- スキーマとの整合性を確認

## 受け入れ条件

### salary 同月重複チェック
- [ ] 同月に複数の手取りを登録できる
- [ ] 編集時も同月の他レコードが存在してもエラーにならない

### dashboard.ts 資金繰りロジック
- [ ] 各支払いの実際の利用月から引き落とし日を算出する
- [ ] 同一カードでも引き落とし日が異なる場合は別エントリとして表示

### テスト
- [ ] `npm run test` が正常に完了する
- [ ] ユーティリティ関数の主要なロジックがテストされている

## スコープ外

- E2Eテスト（Playwright）: DB接続が必要なため今回は対象外
- 統合テスト（Server Actions + Prisma）: DB接続が必要なため今回は対象外
- コンポーネントテスト: 単体テスト完了後に別タスクで検討
