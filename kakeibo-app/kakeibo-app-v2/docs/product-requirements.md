## 用語定義

| 用語 | 定義 |
|------|------|
| 手取り | 給料の支給額（税引後の振込額）。本アプリの「収入」に相当 |
| 利用月（締め月） | クレジットカードの利用が計上される月。Payment テーブルの `month` カラム |
| 引き落とし月 | 実際にクレカ代金が銀行口座から引き落とされる月。利用月 + paymentMonthOffset で算出 |
| 給料サイクル | 給料日から次の給料日前日までの期間。例: 25日支給 → 2/25〜3/24 が「2月の給料サイクル」 |
| 給料日（payDay） | 手取りが振り込まれる日（1-31, 32=末日） |
| 締め日（closingDay） | クレジットカードの利用金額が締められる日（1-31, 32=末日） |
| 支払い日（paymentDay） | クレジットカードの引き落とし日（1-31, 32=末日） |
| 確定日（confirmationDay） | クレジットカード会社が金額を確定する日（任意設定） |
| paymentMonthOffset | 利用月から引き落とし月までの月数差（0=当月, 1=翌月, 2=翌々月）。カード会社により異なる |
| ステータス | 支払いの状態。unconfirmed（未確定）→ confirmed（確定）→ paid（支払済）→ unconfirmed に循環 |

## プロダクト概要

### 名称
**kakeibo-app v2** - 手取りでクレカ代が払えるか一目でわかる家計簿アプリ

### プロダクトコンセプト
- **手取り vs クレカ引き落とし特化**: 汎用家計簿ではなく「今月の手取りで今月の引き落としが賄えるか」に絞る
- **給料サイクルベースの資金繰り**: カレンダー月ではなく、給料日〜次の給料日前日を1サイクルとして管理
- **ステータス管理で安心感**: 未確定→確定→支払済の3段階で、確定していない金額も含めて全体像を把握

### プロダクトビジョン
毎月の手取り額とクレジットカードの引き落とし額を管理し、給料サイクルの中で「手取りで足りるか」をリアルタイムに可視化する。クレカ料金が確定していない状態の金額も計算・表示し、確定/未確定/支払済の内訳を把握できる。

### 目的
- 今月の手取りで今月の引き落としが賄えるかを即座に確認できる
- 引き落とし日が給料日の前か後かを把握し、資金繰りを管理できる
- カテゴリ別の支出を把握し、予算内に収める

## ターゲットユーザー

### プライマリーペルソナ: 田中花子（28歳、会社員）
- クレジットカードを2〜3枚使い分けている
- 毎月の引き落とし額が給料で足りるか不安になることがある
- 既存の家計簿アプリは機能が多すぎて続かなかった
- スマホでサッと確認・入力したい
- 1日の流れ: 買い物後にレシート金額を登録 → 月末にダッシュボードで収支確認

## 成功指標（KPI）

### プライマリーKPI（個人利用の定性目標）
- 継続利用: 2週間の間に3回以上データ入力がある（週1回以上のペース）
- ダッシュボード確認: 給料日・引き落とし日前後に月2回以上確認する習慣がつく

### セカンダリーKPI
- 支払い登録の所要時間: 1件あたり15秒以内
- ページ読み込み時間: 1秒以内

## 機能要件

### コア機能（MVP）

#### F-01: クレジットカード管理

**ユーザーストーリー**:
利用者として、複数のクレジットカードの締め日・支払い日を登録し、引き落としスケジュールを把握したい

**受け入れ条件**:
- [ ] カードの登録・編集・削除ができる（名前、締め日、支払い日、支払月オフセット）
- [ ] バリデーション: name（1-50文字）、closingDay（1-31, 32=末日）、paymentDay（1-31, 32=末日）、paymentMonthOffset（0-2）
- [ ] 締め日・支払い日・確定日の UI 入力: 1〜31 の数値セレクト + 「末日」チェックボックス（チェック時は値を 32 として保存し、セレクトを無効化する）
- [ ] 確定日の設定ができる（任意。confirmationDay が null の場合、confirmationMonthOffset も null とする）
- [ ] カードブランド（Visa/Mastercard/JCB/AMEX/その他）を選択できる。格納値と表示ラベルの対応: visa→"Visa", mastercard→"Mastercard", jcb→"JCB", amex→"American Express", other→"その他"
- [ ] 同一ユーザー内でカード名の重複は許容する（同名カードの区別は id で行う）
- [ ] カードの並び順はドラッグ&ドロップで変更できる（sortOrder に保存）
- [ ] 削除時は確認ダイアログを表示し、関連する支払いもカスケード削除する。sortOrder の欠番は詰め直さない（ドラッグ&ドロップ保存時にのみ正規化する）

**優先度**: P0（必須）

#### F-02: 手取り管理

**ユーザーストーリー**:
利用者として、毎月の手取り額と給料日を登録し、収入を管理したい

**受け入れ条件**:
- [ ] 月別の手取り額・給料日・メモを登録・編集・削除できる
- [ ] バリデーション: month（YYYY-MM 形式）、payDay（1-31, 32=末日）、amount（1 以上の整数）、memo（任意、最大 200 文字）
- [ ] 支給日（payDay）の UI 入力: 1〜31 の数値セレクト + 「末日」チェックボックス（チェック時は値を 32 として保存し、セレクトを無効化する）
- [ ] 金額プリセット: 直近3件の手取り額（重複除外）を候補として表示し、ワンタップで入力できる
- [ ] 一覧は月降順で表示される

**優先度**: P0（必須）

#### F-03: 支払い管理

**ユーザーストーリー**:
利用者として、クレジットカードの利用額を登録し、引き落とし予定を管理したい

**受け入れ条件**:
- [ ] 支払いの登録・編集・削除ができる（カード、利用月、金額、カテゴリ、メモ）
- [ ] ステータスを unconfirmed（未確定）→ confirmed（確定）→ paid（支払済）→ unconfirmed と循環遷移できる
- [ ] カード単位で一括ステータス変更ができる（確定/支払済を選択）
- [ ] 繰り返し支払い（固定費）の登録ができる（指定した利用月を1件目として登録し、翌月・翌々月・3ヶ月後の3件を追加自動生成する。登録操作1回で合計4レコードが作られ、4件すべてが同一の recurringGroupId を持つ）
- [ ] 繰り返し支払いの編集は対象の 1 件のみに適用する（同一グループの他のレコードには反映しない）
- [ ] 繰り返しグループの一括削除ができる（同一 recurringGroupId の支払いを一括削除）
- [ ] 一括登録ができる（ダイアログ形式。STEP1: カード・利用月・合計額を入力 → STEP2: カテゴリごとに金額を振り分け。STEP2 の初期表示は金額入力欄 1 行（カテゴリセレクト＋金額）で、行の追加・削除ができる（最低 1 行。1 行のみの場合は削除ボタンを無効化）。振り分け合計が合計額と一致するまで登録ボタンを無効化）
  - バリデーション: 合計額（1 以上の整数）、各振り分け金額（0 以上の整数、ただし全件 0 は不可）、振り分け先カテゴリは 1 件以上、同一カテゴリの重複選択は不可
- [ ] カテゴリフィルターで支払いを絞り込める
- [ ] メモのキーワード検索ができる
- [ ] 登録時、現在日付（JST: Asia/Tokyo）と比較して自動ステータスを設定する（優先順: paid > confirmed）
  - 引き落とし日 ≤ 今日 → paid
  - 確定日 ≤ 今日（かつ引き落とし日が未来）→ confirmed
    ※ 確定日の算出: 利用月 + confirmationMonthOffset 月の confirmationDay 日（confirmationDay が未設定のカードはこの判定をスキップ）
  - それ以外 → unconfirmed

**優先度**: P0（必須）

#### F-04: ダッシュボード

**ユーザーストーリー**:
利用者として、今月の手取りと引き落としの関係を一目で把握したい

**受け入れ条件**:
- [ ] 月セレクターで表示月を切り替えられる
- [ ] サマリーカード3枚を表示する（集計基準の注記を参照）
  - 手取り合計: 選択月（month = "YYYY-MM"）の全 Salary レコードの amount 合計【月ベース】
  - 支払い合計: 給料サイクル内に引き落とし日が含まれる全 Payment の amount 合計（全ステータス）【サイクルベース。給料サイクルフィルタリング仕様を参照】
  - 残額: 手取り合計 − 支払い合計（括弧内に確定分残額 = 手取り合計 − confirmed・paid 合計を併記）
  - ※ 集計基準の注記: 手取りは月ベース、支払いはサイクルベースで集計する。これは「その月の給料で、そのサイクル内の引き落としを賄えるか」を示すためである
- [ ] ステータス別内訳: 未確定・確定・支払済の金額を表示
- [ ] 支払い予定テーブル: カードごとに折りたたみ表示（初期状態: 全カード展開。当サイクル内の支払いが 0 件のカードも空状態で表示する（「このサイクルに支払いはありません」テキストを 1 行表示）。表示カラム: 利用月・金額・カテゴリ・ステータス・メモ。カード内の支払い行は利用月昇順、同月内は sortOrder 昇順で表示する）
  - 残額がマイナスの場合は赤字（text-destructive）で表示し、警告アイコンを付与する
- [ ] 資金繰りセクション: 給料日と各カードの引き落とし日を時系列で並べ、給料日より前の引き落としには警告アイコンを表示する（給料日と同日の引き落としは警告なし）。同日に複数カードの引き落としがある場合はカードの sortOrder 昇順で並べる
- [ ] 給料サイクルベースでフィルタリングする

**優先度**: P0（必須）

#### F-05: カテゴリ管理

**ユーザーストーリー**:
利用者として、支出をカテゴリ別に分類し、どこにいくら使っているか把握したい

**受け入れ条件**:
- [ ] 新規ユーザーにデフォルトカテゴリ（食費、水道光熱費、通信費、交通費、娯楽、日用品、医療、その他、雑費）を自動作成
- [ ] カスタムカテゴリの追加・編集・削除ができる
- [ ] バリデーション: name（1-30 文字）、color（HEX コード形式、例: "#FF6384"）
- [ ] 同一ユーザー内でカテゴリ名の重複は不可とする（大文字/小文字は区別しない）
- [ ] isDefault = true のデフォルトカテゴリは削除不可とする（name・color の編集は可能）
- [ ] カテゴリの並び順はドラッグ&ドロップで変更できる（sortOrder に保存）
- [ ] 「その他」カテゴリは常に一覧の末尾に表示する（判定条件: isDefault = true かつ name = "その他"。sortOrder に関わらず固定、ドラッグ&ドロップ対象外）
- [ ] カスタムカテゴリ（isDefault = false）の削除時、関連する支払いの categoryId は null になる。sortOrder の欠番は詰め直さない（ドラッグ&ドロップ保存時にのみ正規化する）

**優先度**: P0（必須）

#### F-06: 認証

**ユーザーストーリー**:
利用者として、自分のデータを安全に管理するためにログイン機能が欲しい

**受け入れ条件**:
- [ ] メール+パスワードでログイン・新規登録ができる
- [ ] パスワードリセット（メール送信）ができる
- [ ] ログアウトするとセッションが破棄され /login にリダイレクトされる
- [ ] 未認証ユーザーは /login にリダイレクトされる
- [ ] Supabase Auth の英語エラーを日本語に変換して表示する（例: "Invalid login credentials" → "メールアドレスまたはパスワードが正しくありません"）

**優先度**: P0（必須）

## 給料サイクルフィルタリング仕様

### ロジック
1. 選択月に給料データが存在 → その payDay でサイクル算出
2. 選択月に給料データなし → 最新の給料レコードの payDay を使用
3. 給料データが未登録 → 引き落とし月ベースにフォールバック

### サイクル計算
- 開始: 選択月の payDay 日
- 終了: 翌月の (payDay - 1) 日
- payDay が月の最終日を超える場合は月末日に丸める（例: payDay=31 で2月→2/28開始）
- payDay = 1 の場合: 終了日は当月末日（例: 2月 → 2/1〜2/28）
  ※ 一般ルール「翌月の (payDay - 1) 日」を適用すると翌月0日となるため、当月末日に丸める
- 例: 2月の給料日が25日 → サイクル = 2/25〜3/24

### 候補データの取得範囲
- 利用月 = 選択月の -2, -1, 0, +1 の4ヶ月分を DB から取得する
- 取得後、各支払いの引き落とし日（利用月 + paymentMonthOffset の paymentDay 日）がサイクル内に収まるものを表示対象とする
- 理由: paymentMonthOffset の最大値が 2 のため、2ヶ月前の利用分が当月サイクルに含まれる場合がある

### 支払い日の算出
各支払いの引き落とし日 = 利用月 + paymentMonthOffset 月の paymentDay 日
