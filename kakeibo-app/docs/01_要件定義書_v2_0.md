## 1. コンセプト

**「手取りでクレカ代が払えるかどうか」に特化した家計簿アプリ**。

手取り額（給料の支給額）とクレジットカードの支払い額を管理し、毎月の資金繰りを可視化する。
クレカ料金が確定していない状態（未確定）の金額もリアルタイムで把握し、確定/未確定/支払済の内訳を管理できる。
給料日を基準とした「給料サイクル」で支払いをフィルタリングし、実際の資金繰りに即した表示を行う。

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| 手取り | 給料の支給額（税引後の振込額）。本アプリの「収入」に相当 |
| 利用月（締め月） | クレジットカードの利用が計上される月。Payment テーブルの `month` カラム |
| 引き落とし月 | 実際にクレカ代金が銀行口座から引き落とされる月。利用月 + paymentMonthOffset |
| 給料サイクル | 給料日から次の給料日前日までの期間。例: 25日支給 → 2/25〜3/24 が「2月の給料サイクル」 |
| paymentMonthOffset | 利用月から引き落とし月までの月数差（0〜2）。カード会社により異なる |
| 締め日（closingDay） | クレジットカードの利用が締められる日。32 = 末日 |
| 支払い日（paymentDay） | クレジットカードの引き落とし日 |
| 確認日（confirmationDay） | クレカ明細が確定する日（任意設定）|
| ステータス | 支払いの状態。unconfirmed（未確定）→ confirmed（確定）→ paid（支払済） |

## 7. 給料サイクルフィルタリング仕様

### 概要
支払いデータの表示は、給料日を基準とした「給料サイクル」でフィルタリングする。
これにより、実際の資金繰りに即した表示が可能になる。

### ロジック
1. 選択月に給料データが存在する場合 → その payDay で給料サイクルを算出
2. 選択月に給料データがない場合 → 最新の給料レコードの payDay を使用（**B-1 修正**）
3. 給料データが全く未登録の場合 → 引き落とし月ベースにフォールバック

### 給料サイクルの計算
- サイクル開始: 選択月の payDay 日
- サイクル終了: 翌月の (payDay - 1) 日
- 例: 2月の給料日が25日 → サイクル = 2/25 〜 3/24

### 支払い日の計算
各支払いの実際の引き落とし日 = 利用月 + paymentMonthOffset 月の paymentDay 日
