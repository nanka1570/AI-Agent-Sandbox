## 1. コンセプト

給料日とクレジットカード支払日を管理し、支払い額を可視化できる家計簿アプリ。
クレカ料金が確定していない状態（未確定）の金額もリアルタイムで計算・表示し、確定/未確定/支払済の内訳を把握できる。
**MVP優先**：まず動くものを最短で作り、動いてから拡張する。

## 3. データモデル

### Salary（給料）
| フィールド | 型 | 説明 |
|-----------|-----|------|
| id | String (cuid) | 主キー |
| payDay | Int | 支給日（1-31） |
| amount | Int | 手取り額（円） |
| month | String | 対象月 "2026-03" |
| memo | String? | メモ |
| createdAt | DateTime | 作成日時 |
| updatedAt | DateTime | 更新日時 |

### CreditCard（クレジットカード）
| フィールド | 型 | 説明 |
|-----------|-----|------|
| id | String (cuid) | 主キー |
| name | String | カード名 |
| closingDay | Int | 締め日（1-31） |
| paymentDay | Int | 支払い日（1-31） |
| memo | String? | メモ |
| createdAt | DateTime | 作成日時 |
| updatedAt | DateTime | 更新日時 |
| payments | Payment[] | 支払い一覧（リレーション） |

### Payment（支払い）
| フィールド | 型 | 説明 |
|-----------|-----|------|
| id | String (cuid) | 主キー |
| creditCardId | String | クレカID（外部キー） |
| month | String | 対象月 "2026-03" |
| amount | Int | 確定金額（円） |
| status | String | ステータス: unconfirmed / confirmed / paid |
| memo | String? | メモ |
| createdAt | DateTime | 作成日時 |
| updatedAt | DateTime | 更新日時 |

## 4. Phase 別仕様（厳密ウォーターフォール）

開発方式: **全設計 → 全実装 → 全テスト** の順序を厳守する。

### Phase 0: プロジェクト基盤セットアップ ✅
**コミット:** `chore: kakeibo-app プロジェクト基盤セットアップ`

### Phase 1: Next.js プロジェクト初期化 + DB設計 ✅
**コミット:** `feat: Phase 1 - Next.js初期化 + Prisma DB設計`

### Phase 2: 基本設計
**成果物:** 02_基本設計書、04_画面設計書、06_テスト計画書、テスト環境セットアップ
**コミット:** `docs: Phase 2 - 基本設計（基本設計書 + 画面設計書 + テスト計画書 + テスト環境）`

### Phase 3: 詳細設計
**成果物:** 05_詳細設計書（全機能: クレカ・給料・支払い・ダッシュボード・UI/UX）、07_テスト仕様書（全テストケース）
**コミット:** `docs: Phase 3 - 詳細設計（詳細設計書 + テスト仕様書）`

### Phase 4: 実装
設計書に基づいて全機能を実装する。コミットは機能単位で分割。

**Phase 4a — クレカ管理CRUD**
- /credit-cards: カード形式で一覧表示、登録/編集はダイアログ形式
- バリデーション: name(1-50文字), closingDay(1-31), paymentDay(1-31)
- コミット: `feat: Phase 4a - クレジットカード管理CRUD`

**Phase 4b — 給料管理CRUD**
- /salary: テーブル形式で月別一覧表示
- バリデーション: month(YYYY-MM), payDay(1-31), amount(1以上)
- コミット: `feat: Phase 4b - 給料管理CRUD`

**Phase 4c — 支払い管理**
- /payments: 月別フィルター + テーブル形式
- ステータス: unconfirmed(グレー) → confirmed(青) → paid(緑)
- コミット: `feat: Phase 4c - 支払い管理`

**Phase 4d — ダッシュボード + グラフ**
- /: サマリーカード、支払い予定一覧、棒グラフ(直近6ヶ月)、円グラフ(クレカ別)
- コミット: `feat: Phase 4d - ダッシュボード + グラフ`

**Phase 4e — UI/UXポリッシュ**
- レスポンシブ対応、ローディング、エラー、空状態、トースト通知
- コミット: `feat: Phase 4e - UI/UXポリッシュ`

### Phase 5: テスト
テスト仕様書に基づいて全テストを作成・実行する。

**Phase 5a — 単体テスト + 結合テスト**
- コミット: `test: Phase 5a - 単体テスト + 結合テスト`

**Phase 5b — E2Eテスト + テスト結果報告書**
- コミット: `test: Phase 5b - E2Eテスト + テスト結果報告書 + README`
