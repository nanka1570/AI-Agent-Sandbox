## 3. 認証アーキテクチャ

### 3.1 認証フロー

```
ユーザー → middleware.ts → セッション検証
                               │
                    ┌──────────┴──────────┐
                    ▼                      ▼
              認証済み                  未認証
              → ページ表示              → /login にリダイレクト
```

### 3.2 middleware.ts の処理

1. Supabase SSR クライアントで Cookie からセッションを取得
2. `supabase.auth.getUser()` でセッションをリフレッシュ
3. 公開パス（/login, /register, /forgot-password, /reset-password, /auth/callback, /offline, /privacy, /terms）はスキップ
4. 未認証 → /login にリダイレクト
5. 認証済みで認証ページにアクセス → / にリダイレクト

### 3.3 requireAuth 関数

各 Server Component / Server Action で `requireAuth()` を呼び出し、userId を取得する。
未認証の場合は /login にリダイレクトする。

## 5. データ取得方針

### 5.1 Server Components でのデータ取得

各ページの Server Component が直接 Prisma を呼び出してデータを取得する。
全てのクエリに `where: { userId }` を付与し、マルチテナント分離する。

| ページ | 取得データ |
|--------|----------|
| / (ダッシュボード) | 当月手取り、支払い一覧（給料サイクル or 引き落とし月ベース）、直近6ヶ月支払い、カテゴリ、予算、クレカ一覧 |
| /credit-cards | クレカ一覧 |
| /salary | 手取り一覧 |
| /payments | 支払い一覧（給料サイクル or 引き落とし月ベース）、クレカ一覧、カテゴリ一覧 |
| /budget | カテゴリ一覧、予算一覧、当月支払い一覧 |
| /reports | 選択年の全月手取り・支払い・カテゴリデータ |

### 5.2 データ変更

全てのデータ変更は Server Actions 経由で行う。Server Actions は `"use server"` ディレクティブ付きの関数として定義し、`revalidatePath()` でキャッシュを無効化する。

### 5.3 戻り値形式

```typescript
type ActionResult<T> =
  | { success: true; data: T }
  | { success: false; error: string };
```

## 6. 給料サイクルベースフィルタリング仕様

### 6.1 概要

ダッシュボードと支払い一覧で共通のロジック。給料日を基準に「給料サイクル」を算出し、そのサイクル内に引き落とし日がある支払いのみ表示する。

### 6.2 サイクル計算

```
給料日 = 25日、選択月 = 2月 の場合:
  サイクル開始 = 2月25日
  サイクル終了 = 3月24日

候補の支払いを取得:
  利用月 = currentMonth -2, -1, 0, +1 の4ヶ月分

各支払いの実際の引き落とし日を計算:
  引き落とし日 = 利用月 + paymentMonthOffset 月の paymentDay 日

引き落とし日がサイクル内（cycleStart <= date <= cycleEnd）なら表示対象
```

### 6.3 フォールバック

1. 選択月に給料が登録済み → その payDay を使用
2. 選択月に給料が未登録 → 最新の給料レコードの payDay を使用（B-1 修正）
3. 給料データが全く未登録 → 引き落とし月ベースにフォールバック
   - 引き落とし月が選択月と一致する支払いを表示

## 7. 共通仕様

### 7.1 レイアウト

- **ヘッダー**: アプリ名「家計簿 APP」+ ナビゲーションリンク6つ + ログアウトボタン
- **BottomNav**: モバイル時、下部固定ナビ6タブ
- **コンテンツエリア**: `max-w-5xl mx-auto px-4 pt-6 pb-20 md:pb-6`
- **フッター**: プライバシーポリシー・利用規約リンク
- **フォント**: Geist Sans / Geist Mono
- **言語**: `<html lang="ja">`
- **デザインシステム**: Neo-Brutalism（Retro Pop Edition）

### 7.2 ナビゲーション

| リンク | パス | アイコン |
|--------|------|---------|
| ホーム | / | LayoutDashboard |
| カード | /credit-cards | CreditCard |
| 手取り | /salary | Banknote |
| 支払い | /payments | Receipt |
| カテゴリ/予算 | /budget | Tag |
| レポート | /reports | BarChart3 |

### 7.3 エラーハンドリング方針

| エラー種類 | 処理方法 |
|-----------|---------|
| Zodバリデーションエラー | フォーム上にフィールド単位でエラーメッセージ表示 |
| Server Actions のDBエラー | `{ success: false, error: "メッセージ" }` を返し、トースト通知で表示 |
| ページレンダリングエラー | `error.tsx` でキャッチし、リトライボタンを表示 |
| 認証エラー | /login にリダイレクト |
| 404 | Next.js デフォルトの not-found ページ |

### 7.4 日付・金額の表示形式

| 項目 | 形式 | 例 |
|------|------|-----|
| 対象月 | YYYY年MM月 | 2026年03月 |
| 金額 | ¥N,NNN | ¥150,000 |
| 日付（日のみ） | N日 | 25日 |
