## 3. 認証アーキテクチャ

### 3.1 認証フロー

```
ユーザー → middleware.ts → Supabase SSR クライアント → セッション検証
                                                           │
                                            ┌──────────────┴──────────────┐
                                            ▼                              ▼
                                      認証済み                          未認証
                                      │                                │
                           ┌──────────┴──────────┐              ┌──────┴──────┐
                           ▼                      ▼              ▼              ▼
                      認証ページ？           保護ページ      公開パス？     保護ページ
                      → / にリダ            → 表示         → 表示         → /login へ
                        イレクト                                            リダイレクト
```

### 3.2 middleware.ts の処理フロー

1. `createServerClient` で Supabase SSR クライアントを生成（Cookie 読み書き設定）
2. `supabase.auth.getUser()` でセッションをリフレッシュ（JWT トークン更新）
3. パス判定:
   - 公開パス: `/login`, `/register`, `/forgot-password`, `/reset-password`, `/auth/callback`, `/offline`, `/privacy`, `/terms`
   - 認証ページ: `/login`, `/register`, `/forgot-password`, `/reset-password`
4. 未認証 + 非公開パス → `/login` にリダイレクト
5. 認証済み + 認証ページ → `/` にリダイレクト
6. それ以外 → そのまま通過

### 3.3 middleware matcher

```typescript
export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico).*)"],
};
```

静的アセット以外の全リクエストに適用。

### 3.4 requireAuth 関数

各 Server Component / Server Action で `requireAuth()` を呼び出し、userId を取得する。
未認証の場合は /login にリダイレクトする。全データクエリに `where: { userId }` を付与してマルチテナント分離を実現する。

## 5. データ取得方針

### 5.1 Server Components でのデータ取得

各ページの Server Component が直接 Prisma を呼び出してデータを取得する。
全てのクエリに `where: { userId }` を付与し、マルチテナント分離する。

| ページ | 取得データ | 主なクエリ |
|--------|----------|-----------|
| / (ダッシュボード) | 当月手取り、支払い一覧（給料サイクル or 引き落とし月ベース）、直近6ヶ月支払い、カテゴリ、予算、クレカ一覧 | salary.findMany, payment.findMany (include: creditCard, category), category.findMany, budget.findMany, creditCard.findMany |
| /credit-cards | クレカ一覧 | creditCard.findMany (orderBy: sortOrder) |
| /salary | 手取り一覧 | salary.findMany (orderBy: sortOrder) |
| /payments | 支払い一覧（給料サイクル or 引き落とし月ベース）、クレカ一覧、カテゴリ一覧 | payment.findMany (include: creditCard, category), creditCard.findMany, category.findMany |
| /budget | カテゴリ一覧、予算一覧、当月支払い一覧 | category.findMany, budget.findMany (include: category), payment.findMany |
| /reports | 選択年の全月手取り・支払い・カテゴリデータ | salary.findMany, payment.findMany (include: category), category.findMany |

### 5.2 データ変更

全てのデータ変更は Server Actions 経由で行う。Server Actions は `"use server"` ディレクティブ付きの関数として定義し、`revalidatePath()` でキャッシュを無効化する。

### 5.3 戻り値形式

```typescript
type ActionResult<T> =
  | { success: true; data: T }
  | { success: false; error: string };
```

全ての Server Actions（auth 系を除く）はこの形式で戻り値を返す。

## 6. 給料サイクルベースフィルタリング仕様

### 6.1 概要

ダッシュボードと支払い一覧で共通のロジック。給料日を基準に「給料サイクル」を算出し、そのサイクル内に引き落とし日がある支払いのみを表示する。

### 6.2 サイクル計算

```
給料日 = 25日、選択月 = 2月 の場合:
  サイクル開始 = 2月25日
  サイクル終了 = 3月24日

候補の支払いを取得:
  利用月 = currentMonth -2, -1, 0, +1 の4ヶ月分

各支払いの実際の引き落とし日を計算:
  引き落とし日 = 利用月 + paymentMonthOffset 月の paymentDay 日

引き落とし日がサイクル内（cycleStart <= date <= cycleEnd）なら表示対象
```

### 6.3 フォールバック

| 条件 | 動作 |
|------|------|
| 選択月に給料が登録済み | その payDay を使用してサイクル算出 |
| 選択月に給料が未登録 | 最新の給料レコードの payDay を使用（B-1 修正） |
| 給料データが全く未登録 | 引き落とし月ベースにフォールバック（引き落とし月が選択月と一致する支払いを表示） |

### 6.4 自動ステータス設定

支払い登録時、カードの設定に基づいてステータスを自動計算する:

| 条件 | 設定されるステータス |
|------|-------------------|
| 引き落とし日が過去 | paid |
| 確定日が過去（引き落とし日は未来） | confirmed |
| それ以外 | unconfirmed |

### 6.5 資金繰り判定

```
給料日 = 25日 の場合:
  引き落とし日 >= 25日 → 「入金後」（安全）
  引き落とし日 < 25日 → 「入金前」（注意）
  翌月以降の引き落とし → 常に「入金後」（安全）
```

## 7. 共通仕様

### 7.1 レイアウト

- **ヘッダー**: アプリ名「家計簿 APP」+ ナビゲーションリンク6つ + ログアウトボタン
- **BottomNav**: モバイル時、下部固定ナビ6タブ（md 未満で表示）
- **コンテンツエリア**: `max-w-5xl mx-auto px-4 pt-6 pb-20 md:pb-6`
- **フッター**: プライバシーポリシー・利用規約リンク（border-t 付き）
- **フォント**: Geist Sans / Geist Mono
- **言語**: `<html lang="ja">`
- **デザインシステム**: Neo-Brutalism（Retro Pop Edition）
  - ボーダー: `border-2 border-border`
  - シャドウ: `shadow-[4px_4px_0px_0px_rgba(0,0,0,1)]`
  - ホバー: `hover:-translate-x-px hover:-translate-y-px`

### 7.2 ナビゲーション

| 順番 | リンク | パス | アイコン |
|------|--------|------|---------|
| 1 | ホーム | / | LayoutDashboard |
| 2 | カード | /credit-cards | CreditCard |
| 3 | 手取り | /salary | Banknote |
| 4 | 支払い | /payments | Receipt |
| 5 | カテゴリ/予算 | /budget | Tag |
| 6 | レポート | /reports | BarChart3 |

- PC: ヘッダー内に `hidden md:flex` で表示
- モバイル: BottomNav に `md:hidden` で表示

### 7.3 エラーハンドリング方針

| エラー種類 | 処理方法 |
|-----------|---------|
| Zodバリデーションエラー | フォーム上にフィールド単位でエラーメッセージ表示 |
| Server Actions のDBエラー | `{ success: false, error: "メッセージ" }` を返し、トースト通知で表示 |
| ページレンダリングエラー | `error.tsx` でキャッチし、リトライボタンを表示 |
| 認証エラー | middleware で /login にリダイレクト |
| Supabase Auth エラー | 英語メッセージを日本語に変換してフォーム上に表示 |
| 404 | Next.js デフォルトの not-found ページ |

### 7.4 日付・金額の表示形式

| 項目 | 形式 | 例 |
|------|------|-----|
| 対象月 | YYYY年MM月 | 2026年03月 |
| 金額 | ¥N,NNN | ¥150,000 |
| 日付（日のみ） | N日 | 25日 |
| 月ラベル | M月 | 3月 |
