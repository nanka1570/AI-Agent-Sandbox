## 用語定義

| 用語 | 定義 |
|------|------|
| 使えるお金（AvailableMoney） | `Σ銀行口座残高 + 未入金の給料 − 全支払い − 請求明細差額` で算出する、現時点で自由に使える金額 |
| 銀行口座（Account） | ユーザーが手動で残高を管理する銀行口座または現金。複数登録可 |
| 手取り | 給料の支給額（税引後の振込額）。本アプリの「収入」に相当 |
| 利用日（usageDate） | 支払いが発生した日（カレンダー入力の軸となる） |
| 利用月 | クレジットカードの利用が計上される月（`YYYY-MM`）。Payment の `month` カラム |
| 引き落とし月 | 実際にクレカ代金が銀行口座から引き落とされる月。利用月 + `paymentMonthOffset` で算出 |
| 給料サイクル | 給料日から次の給料日前日までの期間 |
| 給料日（payDay） | 手取りが振り込まれる日（1-31, 32=末日） |
| 締め日（closingDay） | クレジットカードの利用金額が締められる日 |
| 支払い日（paymentDay） | クレジットカードの引き落とし日 |
| 確定日（confirmationDay） | クレジットカード会社が金額を確定する日（任意設定） |
| 請求明細（CreditCardStatement） | カード会社が確定した月次請求額。登録済 Payment 合計との差額を誤差ゼロ管理に用いる |
| 誤差ゼロ管理 | 登録した Payment 合計と請求明細の確定額を突き合わせ、差額 0 円を目指す運用 |
| CSV インポート | カード会社・銀行からダウンロードした CSV 明細をアップロードして Payment を一括登録する機能 |
| ステータス | 支払いの状態。unconfirmed（未確定）→ confirmed（確定）→ paid（支払済）に遷移 |

## プロダクト概要

### 名称
**kakeibo-app v3** — 「支払いを全部払った後にいくら残るか」がわかる家計簿アプリ

### プロダクトコンセプト
- **使えるお金の可視化**: 銀行残高と手取り収入から、未確定クレカ利用を含む全支払いを差し引き、「今使って良い金額」をひとつの数字で示す
- **クレカ誤差ゼロ管理**: 利用明細を 1 円単位で積み上げ、カード会社の請求確定額と突き合わせ、差額 0 円の状態を目指す。CSV インポートで登録の手間を最小化
- **Zaim 的な日常操作感**: カレンダー UI でタップ入力、月次レポート（円グラフ・棒グラフ）で振り返り、手動口座連携で残高を一元管理

### プロダクトビジョン
多くの家計簿アプリはクレジットカード利用を「月末にまとめて表示」するため、実際に引き落とされるまで「使えるお金」が不透明になる。kakeibo-app v3 は、クレカ利用を即座に反映し、誤差ゼロで照合することで、ユーザーが毎日「あといくら使えるか」を根拠を持って知れる状態を作る。Zaim のような直感的な入力体験と、必要十分な可視化を両立させる。

### 目的
- 複数カードの利用を 1 円単位で管理し、請求確定額と誤差ゼロに保つ
- 銀行残高・手取り・全支払いを統合した「使えるお金」を常時ワンスクリーンで確認できる
- CSV とカレンダー入力で登録負荷を下げ、日常的に使い続けられる

## ターゲットユーザー

### プライマリーペルソナ: 田中花子（28 歳、会社員）
- クレジットカードを 2〜3 枚使い分けている
- 給料は月 1 回、25 日振込
- 引き落とし額の不確定さで「いま本当にいくら使って良いか」わからず不安になる
- Zaim や Money Forward を試したが、クレカ反映の遅さと誤差に不満
- 銀行 API 連携は不要、手動残高更新でよい（セキュリティ懸念）
- 1 日の流れ: 買い物後にカレンダー画面で金額を登録 / 月初にカード会社から CSV をダウンロードして一括登録 / 月末に請求明細と照合 / 毎朝「使えるお金」を確認

### セカンダリーペルソナ: 佐藤健一（35 歳、フリーランスエンジニア）
- 経費精算用のカードと生活用のカードを分けている
- 収入が月によって変動するため「いま本当にいくら自由に使えるか」の可視化ニーズが強い
- CSV 一括登録を重視

## 成功指標（KPI）

個人利用前提の定性・定量目標として設定する。

### プライマリーKPI
- **継続利用**: リリース後 3 ヶ月時点で週 1 回以上データ入力する状態が維持されている
- **誤差ゼロ達成率**: 「登録済み CreditCardStatement のうち、`withdrawnAmount` 入力時点で差額 0 円で確定したものの比率」が 90% 以上
  - 分母: `withdrawnAmount` が入力済みの CreditCardStatement 件数（= 引落済みとして確定したカード×月の組数）
  - 分子: 上記のうち差額（ΣPayment − confirmedAmount）が 0 円のもの
  - Statement 未登録の月はカウント対象外
- **使えるお金の確認頻度**: ダッシュボード確認が週 3 回以上

### セカンダリーKPI
- **CSV インポート 1 回あたりの登録所要時間**: 10 件の明細を 60 秒以内で登録完了
- **Payment 1 件の手動入力時間**: 15 秒以内
- **ダッシュボード読み込み時間**: 1 秒以内

## 機能要件

### コア機能（MVP）

#### F-01: 認証

**ユーザーストーリー**:
ユーザーとして、個人のデータを安全に管理するために、メール＋パスワードでサインイン／サインアップしたい。

**受け入れ条件**:
- [ ] メールアドレス＋パスワードで新規登録できる
- [ ] 登録したメールアドレス＋パスワードでログインできる
- [ ] ログアウトできる
- [ ] パスワードリセット（メールリンク送信）ができる
- [ ] 未認証ユーザーは `/login` にリダイレクトされる
- [ ] 認証エラーメッセージは日本語で表示される

**優先度**: P0（必須）

#### F-02: 銀行口座管理（Account）

**ユーザーストーリー**:
ユーザーとして、「使えるお金」の計算に含めるため、自分の銀行口座や現金を手動で登録・残高更新したい。

**受け入れ条件**:
- [ ] 口座の新規登録・編集・削除ができる（フィールド: 名前・種別（bank / cash）・残高・並び順）
- [ ] 残高を手動で更新でき、更新日時（`balanceUpdatedAt`）が記録される
- [ ] 残高更新時に BalanceHistory に履歴が 1 件追加される
- [ ] 同一ユーザー内で口座名の重複は許容する（「三井住友 A」「三井住友 B」等を想定）
- [ ] 口座を削除しても、過去の BalanceHistory は論理的に残る（将来の参照用）

**優先度**: P0（必須）

#### F-03: 手取り管理（Salary）

**ユーザーストーリー**:
ユーザーとして、給料サイクルごとの資金繰りを計算するために、月別の手取り額を登録・編集したい。

**受け入れ条件**:
- [ ] 月ごとに手取り額と給料日（payDay: 1-31, 32=末日）を登録できる
- [ ] 同月に複数件の登録を許容する（ボーナス等）
- [ ] 一覧・編集・削除ができる
- [ ] 未来月の登録も許容する（将来の資金繰り計算用）

**優先度**: P0（必須）

#### F-04: クレジットカード管理（CreditCard）

**ユーザーストーリー**:
ユーザーとして、利用月から引き落とし月を自動計算するために、各カードの締め日・支払日・確定日を登録したい。

**受け入れ条件**:
- [ ] カード名・締め日（closingDay）・支払日（paymentDay）・支払月オフセット（paymentMonthOffset: 0-2）を登録できる
- [ ] 確定日（confirmationDay）・確定月オフセット（confirmationMonthOffset）を任意で登録できる
- [ ] 31 日以降は「末日」として扱う（UI は「末日」選択肢）
- [ ] 一覧・編集・削除ができる
- [ ] 同名カードの重複は許容する
- [ ] 引き落とし先の銀行口座（accountId）を任意で紐付けられる（引落時の残高減算用）

**優先度**: P0（必須）

#### F-05A: カテゴリ管理（Category）

**ユーザーストーリー**:
ユーザーとして、支出を分類するために、カテゴリを管理したい。

**受け入れ条件**:
- [ ] カテゴリを新規作成・編集・削除できる（名前・色・並び順）
- [ ] デフォルトカテゴリ（食費・日用品・交通・娯楽・その他など）が初回ログイン時に作成される
- [ ] 「その他」カテゴリはデフォルトから削除できず、末尾固定で表示される

**優先度**: P0（必須）

#### F-05B: 予算管理（Budget）

**ユーザーストーリー**:
ユーザーとして、カテゴリ別に使い過ぎを防ぐために、月別予算を設定して消化率を確認したい。

**受け入れ条件**:
- [ ] カテゴリ × 月の組み合わせで予算額を登録できる
- [ ] 同一 (userId, categoryId, month) の Budget は UNIQUE 制約で 1 件のみ
- [ ] 月別の予算消化率を算出できる（F-09 ダッシュボード・F-11 レポートで利用）

**優先度**: P1（重要・MVP 後期に実装）

#### F-06: 支払い管理（Payment）

**ユーザーストーリー**:
ユーザーとして、クレカや現金の支出を記録するために、利用日・金額・カテゴリ・支払い元（カードまたは口座）を登録したい。

**受け入れ条件**:
- [ ] Payment を新規登録・編集・削除できる（フィールド: usageDate, month, amount（Int円単位）, categoryId, creditCardId? または accountId?, memo, isRecurring, recurringGroupId）
- [ ] `usageDate` は日単位で必須
- [ ] `month` の自動導出ルール（支払元により分岐）:
  - **クレカ利用**: `usageDate` が該当カードの `closingDay` 以前なら「その月」、超過していれば「翌月」を `month` とする（例: 締め日 15 日のカードで 3/16 利用 → `month = "2026-04"`）
  - **現金・口座利用**: `usageDate` のカレンダー月をそのまま `month` とする
  - ユーザーが `month` を手動上書きすることも可（特殊ケース対応）
- [ ] ステータスは unconfirmed / confirmed / paid の 3 段階、確定日・引落日で自動遷移
- [ ] 一覧は月フィルター・カードフィルター・カテゴリフィルター・キーワード検索に対応
- [ ] 繰り返し登録（`isRecurring=true`, 本体 + 3 件 = 計 4 件）が可能
- [ ] 一括ステータス変更、一括削除が可能

**優先度**: P0（必須）

#### F-07: CSV 明細インポート（MVP 版）

**ユーザーストーリー**:
ユーザーとして、登録の手間を減らすために、カード会社からダウンロードした CSV 明細をアップロードして Payment を一括登録したい。

**MVP スコープ（P0）**:
- [ ] `/payments/import` ページで CSV ファイルをアップロードできる
- [ ] 対象カードを 1 枚選択してインポートする（複数カード混在ファイルは非対応）
- [ ] ヘッダー行を自動検出し、列マッピング UI で「日付列 / 金額列 / 摘要列」の 3 列をユーザーが指定できる（他の列は無視）
- [ ] プレビュー画面でパース結果テーブル（日付・金額・摘要）と件数・合計額を表示
- [ ] 既存 Payment との重複（usageDate + amount + cardId で判定）を行に赤マーク表示
- [ ] 重複行をチェックボックスで対象外にできる
- [ ] カテゴリはプレビュー画面でデフォルト「その他」、行ごとにプルダウンで変更可
- [ ] 確認ボタンで `status="confirmed"` の Payment を一括登録、結果画面で件数と合計を表示
- [ ] パースエラー行はエラー理由を表示し、自動的にスキップする

**MVP スコープ外（Post-MVP へ → F-12 に分離）**:
- カード別プリセットの localStorage 保存
- 銀行口座 CSV のインポート
- カテゴリ自動推測
- 複数カード混在ファイルの扱い

**優先度**: P0（必須）

#### F-08: クレカ誤差ゼロ照合（CreditCardStatement）

**ユーザーストーリー**:
ユーザーとして、カード会社の請求確定額と自分の登録データが一致しているか確認し、差額ゼロで管理するために、月ごとに請求明細を登録して差額を可視化したい。

**受け入れ条件**:
- [ ] `/credit-cards/[id]/reconcile` ページでカード × 利用月の請求明細を登録できる（confirmedAmount 必須）
- [ ] 該当月の Payment 一覧と合計金額を同画面に表示する
- [ ] 差額 `statementGap = ΣPayment(該当カード×該当月) − confirmedAmount` をバナー表示（差額 0 円なら OK バッジ、正負どちらの場合も絶対値で強調表示）
- [ ] 引落実額（withdrawnAmount）と引落日（withdrawnAt）を入力できる
- [ ] 引落入力時、紐付いた Account.balance を withdrawnAmount 分自動減算し、BalanceHistory に記録
- [ ] 同一 (userId, creditCardId, month) の明細は 1 件のみ（UNIQUE 制約）

**`statementGap` の AvailableMoney への算入ルール**:
- Statement が登録済み **かつ** `withdrawnAmount` 未入力 の組のみを差額算入対象とする
- 対象組について `statementGap` を **符号そのまま** AvailableMoney から減算（正の差額は Payment 側が多いので減算、負の差額は加算として働く）
- Statement 未登録のカード×月は差額算入せず、ΣPayment をそのまま減算（= 現行の登録データを信じる）
- `withdrawnAmount` 入力済みの組は引落済として Account.balance に反映済みのため、二重計上を避けて AvailableMoney 計算から除外

**優先度**: P0（必須）

#### F-09: ダッシュボード（AvailableMoney 中心）

**ユーザーストーリー**:
ユーザーとして、「今いくら使えるか」を即座に把握するために、銀行残高・手取り・全支払いを統合した AvailableMoney をメイン指標として常時確認したい。

**受け入れ条件**:
- [ ] トップページ `/` に AvailableMoney を大きく表示する
- [ ] 内訳（accountsTotal / incomingSalary / unpaidPayments / statementGap）をセカンダリーカードで表示
- [ ] 現在の給料サイクル（開始日〜終了日）を表示
- [ ] カード別支払い予定表（引落日順）を表示
- [ ] ステータス内訳（unconfirmed / confirmed / paid）を集計表示
- [ ] 予算消化率（カテゴリ別）を表示（F-05B 実装後に有効化、未実装時は非表示）
- [ ] AvailableMoney がマイナスの場合は赤色で強調

**空状態・初回セットアップ時の挙動**:
- [ ] 口座未登録の場合: 「使えるお金を計算するには銀行口座を登録してください」バナーと `/accounts` への導線
- [ ] 給料未登録の場合: 「給料を登録するとサイクル資金繰りが計算できます」バナーと `/salary` への導線
- [ ] カード未登録の場合: カード別支払い予定表をスキップして「カードを登録すると請求予定が表示されます」と表示
- [ ] Payment 未登録の場合: ステータス内訳と予算消化率をスキップし、「支出を登録してみましょう」と `/calendar` への導線
- [ ] 初回ログイン直後は、上記 4 バナーが画面上部に順次表示される（完了するごとに該当バナーが消える）

**優先度**: P0（必須）

#### F-10: カレンダー入力

**ユーザーストーリー**:
ユーザーとして、日々の支出をその場で記録するために、カレンダー画面で日付を選び、即座に支払いを登録したい。

**受け入れ条件**:
- [ ] `/calendar` ページで月カレンダーを表示する
- [ ] 各日セルにその日の支払い合計額を表示する
- [ ] 日付をタップすると `QuickPaymentDialog` が開き、金額・カテゴリ・支払元（カード or 口座）を選んで登録できる
- [ ] 登録後、該当日セルの合計額が即座に更新される
- [ ] 月切り替え（前月 / 翌月）ができる

**優先度**: P0（必須）

#### F-11: 月次レポート

**ユーザーストーリー**:
ユーザーとして、支出傾向を振り返るために、月次のカテゴリ別支出を円グラフで、月次推移を棒グラフで見たい。

**受け入れ条件**:
- [ ] `/reports` ページでカテゴリ別支出の円グラフを表示（Recharts）
- [ ] 直近 12 ヶ月の月次支出推移を棒グラフで表示
- [ ] 月ピッカーで対象月を切り替えできる
- [ ] 予算に対する消化率を棒グラフ上に重ねて表示

**優先度**: P0（必須）

## 非機能要件

### パフォーマンス
- ダッシュボード初期表示: 1 秒以内（Payment 500 件、Account 5 件、Card 3 枚を想定）
- CSV インポート: 100 行のファイルを 3 秒以内にパース＆プレビュー表示
- 一括登録: 100 件の Payment を 2 秒以内に DB 登録

### ユーザビリティ
- 新規ユーザーが初回セットアップ（口座 1 件＋給料 1 件＋カード 1 枚＋カテゴリ確認）を 5 分以内に完了できる
- Payment 1 件の入力（カレンダー経由）が 15 秒以内
- モバイルファースト（スマホ縦画面での操作を主、タブレット / PC は拡張）

### 信頼性
- データ損失ゼロ（Supabase Postgres の自動バックアップに依存）
- CSV インポートはトランザクション単位で実行し、エラー時はロールバック
- ステータス自動遷移は決定論的（日時と設定値のみから算出、順序非依存）

### セキュリティ
- Supabase Auth によるメール＋パスワード認証
- Row Level Security（全テーブルで `auth.uid() = user_id` ポリシー）
- パスワードは Supabase 側でハッシュ化（自前管理しない）
- CSV ファイルはサーバーに保存せず、パース後は破棄する

### スケーラビリティ
- Vercel + Supabase 構成で個人利用規模（最大数万件 Payment）を想定
- 大規模多人数利用（数万人）は MVP の対象外

## スコープ外（明示）

以下は本 MVP では実装せず、必要に応じて Post-MVP で検討する。

- 銀行・カード API による自動連携（手動更新と CSV インポートのみ）
- レシート OCR
- PWA / オフライン対応
- マルチユーザー共有（家族アカウント）
- モバイルネイティブアプリ
- 多通貨対応（円のみ）
- 投資・資産運用機能（株式・暗号資産等）
- 請求書払いの管理（クレカと現金のみ）
- 自動カテゴリ推測（CSV インポート時も手動割当のみ）
