# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**claude-code-like** - ターミナルで動く AI ペアプログラマー

### プロダクトコンセプト
- **Tool Use ベースの自律的エージェント**: AI がファイルの読み書き、コマンド実行、コード検索を自律的に行い、開発タスクを遂行する
- **機密案件対応のセキュアな設計**: SaaS 仲介層を排除し、Anthropic API への直接通信のみ。送信内容の完全な把握、通信ログの監査、テレメトリなしを実現する
- **プロジェクト適応**: CLAUDE.md を自動読み込みし、プロジェクト固有のルールやコンテキストに従って動作する
- **拡張可能なワークフロー**: コマンド / スキル / サブエージェントにより、定型作業の自動化やAIの振る舞いカスタマイズが可能

### プロダクトビジョン
機密性の高い案件に従事する開発者が、ソースコードを外部 SaaS に送ることなく、ターミナル上で AI ペアプログラミングを行える CLI ツールを提供する。
Anthropic Claude の Tool Use 機能を活用し、ファイル操作・シェル実行・コード検索を AI が自律的に行う。
API キーベースの直接通信のみを使用し、仲介サービスを経由しないため、データの流れを組織で完全に管理できる。
コマンド・スキル・サブエージェントによるワークフロー拡張機構を備え、スペック駆動開発などの定型プロセスを自動化できる。
Claude Code の核となる仕組みを自作することで、AI Agent の設計パターンを深く理解する学習プロジェクトでもある。

### セキュリティの差別化ポイント
| 観点 | SaaS 型 AI ツール | claude-code-like |
|------|-------------------|------------------|
| 通信経路 | SaaS サーバー経由（不透明） | Anthropic API 直接通信（コードで検証可能） |
| 送信データ | 何が送られるか不明 | 送信内容をコードレベルで把握可能 |
| 通信ログ | 取得不可 | `--debug` で全通信をローカル記録 |
| テレメトリ | あり（オプトアウト不可の場合も） | 一切なし |
| ソースコード | クローズド | オープンソース（通信経路を誰でも検証可能） |

### 目的
- 機密性の高い案件でも利用可能な、ローカル完結型の AI ペアプログラミング体験を提供する
- Tool Use（Function Calling）ベースの Agent ループを実装し、AI Agent の設計パターンを学ぶ
- CLAUDE.md によるプロジェクト固有コンテキストの注入機構を実現する

## ターゲットユーザー

### プライマリーペルソナ: 機密案件に従事する開発者
- NDA や情報セキュリティポリシーにより、SaaS 型 AI ツール（ChatGPT、GitHub Copilot 等）の利用が制限されている
- ターミナル中心の開発環境で作業する
- AI のコーディング支援は受けたいが、ソースコードを外部サービスに送信することへの懸念がある
- API キーベースで通信先を自組織で管理できるツールなら利用許可が下りる環境にいる
- TypeScript / Node.js での開発経験がある
- 1日のワークフロー: ターミナルでコード編集 → AI に質問/指示 → AI がコードを読み書き → 結果を確認（全てローカル + API 直接通信で完結）

## 成功指標（KPI）

### プライマリーKPI
- MVP 完成: コア機能（C-01〜C-11）が全て動作する
- 対話ループの安定性: 10ターン以上の連続会話でプロセスクラッシュ・未捕捉例外なく動作する（E2E テスト `tests/e2e/basic-conversation.test.ts` で検証）
- ツール実行成功率: 単体テストスイートにおいて、各ツールの正常系テストケースで 95% 以上が成功すること（`vitest run` で計測、MVP 完成時点）

### セカンダリーKPI
- 拡張機能（E-01〜E-05）の実装完了（MVP 完成後のフェーズ 2 で対応。各機能の受け入れ条件が全て満たされること。ロジック系は `vitest run` で自動検証、表示系（E-03）は手動確認: Markdown の見出し・コードブロック・太字がターミナルで視覚的に区別でき、ツール名が色付きで表示されること）
- テストカバレッジ: ツール単体テスト 80% 以上（MVP 完成時点で `npm run test:coverage` により計測）

## 機能要件

### コア機能（MVP）

#### C-01: 対話ループ（REPL）

**ユーザーストーリー**:
機密案件の開発者として、外部 SaaS を経由せずターミナル上で AI と対話的にやり取りするために、REPL 形式の入力・応答ループが欲しい

**受け入れ条件**:
- [ ] `node:readline/promises` で入力を受け付ける
- [ ] Anthropic SDK のストリーミング API でトークンをリアルタイム表示する
- [ ] 複数ターンの会話コンテキスト（messages 配列）を維持する
- [ ] `exit` / `quit` 入力で正常終了する
- [ ] `Ctrl+C` で現在の応答を中断し、次の入力を受け付ける
- [ ] 空入力は無視して再度プロンプトを表示する
- [ ] `max_tokens` に達した場合、応答が途中で切れている旨をユーザーに通知し、次の入力を受け付ける

**優先度**: P0（必須）

#### C-02: Read ツール

**ユーザーストーリー**:
AI として、ユーザーが指定したファイルの内容を確認するために、ファイル読み取りツールが欲しい

**受け入れ条件**:
- [ ] 指定パスのファイル内容を読み取り、行番号付きで返却する
- [ ] `offset`（開始行）と `limit`（行数）パラメータで部分読み取りに対応する
- [ ] 存在しないファイルの場合、エラーメッセージを返却する
- [ ] バイナリファイルの場合（null バイトが含まれるファイルを基準に判定）、「バイナリファイルのため読み取りをスキップしました」と返却する

**優先度**: P0（必須）

#### C-03: Write ツール

**ユーザーストーリー**:
AI として、新しいファイルを作成したり既存ファイルを更新するために、ファイル書き込みツールが欲しい

**受け入れ条件**:
- [ ] 指定パスにファイルを作成/上書きする
- [ ] 既存ファイルの上書き時はユーザーに確認プロンプトを表示する
- [ ] 新規ファイル作成時は確認なしで即座に書き込む（既存ファイルの上書きのみ確認対象）
- [ ] 親ディレクトリが存在しない場合は自動作成する
- [ ] 書き込み完了後、ファイルパスと行数を返却する

**優先度**: P0（必須）

#### C-04: Edit ツール

**ユーザーストーリー**:
AI として、ファイルの一部を正確に編集するために、old_string → new_string 方式の部分編集ツールが欲しい

**受け入れ条件**:
- [ ] `file_path`, `old_string`, `new_string` パラメータを受け取る
- [ ] `old_string` に完全一致する部分を `new_string` に置換する
- [ ] 変更前後の diff を表示する
- [ ] `old_string` が見つからない場合、エラーメッセージを返却する
- [ ] `old_string` が複数箇所にマッチする場合、エラーメッセージを返却する

**優先度**: P0（必須）

#### C-05: Bash ツール

**ユーザーストーリー**:
AI として、ビルドやテスト等のシェルコマンドを実行するために、コマンド実行ツールが欲しい

**受け入れ条件**:
- [ ] 指定されたシェルコマンドを `child_process` で実行する
- [ ] 実行前にユーザーに確認プロンプトを表示する
- [ ] ユーザーが拒否した場合、`is_error: true` でツール結果を返却し、エージェントループを継続する
- [ ] stdout と stderr を返却する
- [ ] タイムアウト（デフォルト120秒）を設定し、超過時はプロセスを kill し、`is_error: true` でエラーメッセージをエージェントループに返却する
- [ ] 終了コードを返却する

**優先度**: P0（必須）

#### C-06: Glob ツール

**ユーザーストーリー**:
AI として、プロジェクト内のファイルを素早く見つけるために、glob パターンによるファイル検索ツールが欲しい

**受け入れ条件**:
- [ ] glob パターンでファイルパスを検索する（`fast-glob` 使用）
- [ ] `node_modules/`, `.git/`, `dist/` をデフォルトで除外する
- [ ] 検索ディレクトリを指定可能にする（デフォルト: cwd）
- [ ] マッチしたファイルパスの一覧を返却する

**優先度**: P0（必須）

#### C-07: Grep ツール

**ユーザーストーリー**:
AI として、コードベース内の特定のパターンを検索するために、正規表現によるコンテンツ検索ツールが欲しい

**受け入れ条件**:
- [ ] 正規表現パターンでファイル内容を検索する
- [ ] マッチした行の行番号とコンテキスト（前後の行、デフォルト 2 行）を返却する
- [ ] 検索対象のファイルパターン（glob）を指定可能にする
- [ ] バイナリファイルはスキップする
- [ ] `node_modules/`, `.git/` をデフォルトで除外する

**優先度**: P0（必須）

#### C-08: システムプロンプト管理

**ユーザーストーリー**:
開発者として、プロジェクト固有のルールを AI に自動で伝えるために、CLAUDE.md の自動読み込み機能が欲しい

**受け入れ条件**:
- [ ] 起動時にカレントディレクトリの `CLAUDE.md` を検索する
- [ ] 存在する場合、その内容をシステムプロンプトに注入する
- [ ] 存在しない場合はスキップし、デフォルトのシステムプロンプトのみ使用する
- [ ] 基本のシステムプロンプトには、ツール使用方針やコーディングアシスタントとしての振る舞いを定義する

**優先度**: P0（必須）

#### C-09: コマンドシステム

**ユーザーストーリー**:
開発者として、定型作業を `/コマンド名` で即座に実行するために、Markdown ベースのコマンド定義システムが欲しい

**受け入れ条件**:
- [ ] `.commands/*.md` ファイルをコマンド定義として読み込む
- [ ] ファイル名（拡張子除く）をコマンド名として認識する
- [ ] YAML frontmatter で `description` と `allowed-tools` を定義できる
- [ ] `allowed-tools` は現時点では宣言のみ保持し、ツール使用の実際の制限は行わない（将来の拡張ポイント）
- [ ] `/コマンド名` 入力でコマンドの Markdown 内容をシステムプロンプトに注入し、AI に実行させる
- [ ] `/help` で利用可能なコマンド一覧と説明を表示する
- [ ] コマンドが見つからない場合、エラーメッセージを表示する

**優先度**: P0（必須）

#### C-10: スキルシステム

**ユーザーストーリー**:
開発者として、AI の振る舞いを特定のドメイン知識やテンプレートで拡張するために、スキル読み込み機構が欲しい

**受け入れ条件**:
- [ ] `.skills/[name]/SKILL.md` をスキル定義として読み込む
- [ ] SKILL.md は YAML frontmatter（description 等）+ Markdown ガイドで構成する
- [ ] 同ディレクトリの `template.md` やその他のファイルもスキルの一部として読み込める
- [ ] AI が `Skill('name')` を呼び出すと、スキル内容をコンテキストに注入する
- [ ] スキルの一覧取得と内容確認ができる

**優先度**: P0（必須）

#### C-11: サブエージェント

**ユーザーストーリー**:
開発者として、メインの会話を中断せずに並行タスク（コードレビュー、テスト実行等）を委譲するために、独立したコンテキストで動作するサブエージェントが欲しい

**受け入れ条件**:
- [ ] `.agents/[name].md` ファイルをサブエージェント定義として読み込む
- [ ] YAML frontmatter で `name`, `description`, `tools`（使用可能ツール一覧）を定義できる
- [ ] メイン会話とは独立した messages 配列で API を呼び出す
- [ ] サブエージェントが使用できるツールを `tools` フィールドで制限する（C-09 の `allowed-tools` と異なり、MVP 時点で実際のツール呼び出し制限を実装する）
- [ ] サブエージェントの実行結果をメイン会話に返却する
- [ ] サブエージェント一覧の取得ができる

**優先度**: P0（必須）

### CLI インターフェース

```bash
# 起動
npx claude-code-like

# 開発モード
npm run dev

# デバッグモード（API 通信ログをローカルに記録）
npm run dev -- --debug

# 会話の再開
npm run dev -- --resume [conversation-id]

# 過去の会話一覧を表示
npm run dev -- --list

# 対話例
> このプロジェクトの構造を教えて
# → AI が Glob ツールでファイル一覧を取得し、構造を説明

> src/index.ts を読んで
# → AI が Read ツールでファイルを読み取り、内容を解説

> package.json に "description" フィールドを追加して
# → AI が Read → Edit の順でツールを使い、ファイルを編集
```

### 拡張機能（Post-MVP）

#### E-01: 会話履歴永続化

**ユーザーストーリー**:
開発者として、過去の会話を途中から再開するために、会話履歴の保存・復元機能が欲しい

**受け入れ条件**:
- [ ] 会話を JSON ファイルとして `~/.claude-code-like/conversations/` に自動保存する
- [ ] `--resume [conversation-id]` で指定した会話を再開できる（ID 省略時は最新の会話を自動選択）
- [ ] `--list` フラグで過去の会話一覧を表示できる
- [ ] 各会話にはタイムスタンプとサマリー（最初のユーザーメッセージ）を付与する
- [ ] SIGINT / SIGTERM 受信時に会話履歴を即時保存してから終了する

**優先度**: P1（重要）

#### E-02: 設定ファイル

**ユーザーストーリー**:
開発者として、モデルやタイムアウト値をカスタマイズするために、設定ファイルが欲しい

**受け入れ条件**:
- [ ] `~/.claude-code-like/config.json` から設定を読み込む
- [ ] 設定項目とデフォルト値:
  - model: 使用モデル（デフォルト: `claude-sonnet-4-20250514`。具体的な識別子は functional-design.md の AppConfig 型定義を正とする）
  - maxTokens: 最大トークン数（デフォルト: 8192）
  - timeout: Bash タイムアウト秒数（デフォルト: 120）
  - theme: 配色テーマ（デフォルト: `default`）
- [ ] 設定ファイルが存在しない場合はデフォルト値を使用する
- [ ] 環境変数 `ANTHROPIC_API_KEY` から API キーを取得する

**優先度**: P1（重要）

#### E-03: 表示改善

**ユーザーストーリー**:
開発者として、AI の応答を読みやすく確認するために、Markdown レンダリングやシンタックスハイライトが欲しい

**受け入れ条件**:
- [ ] AI 思考中に `ora` によるスピナーを表示する
- [ ] Markdown を `marked` + `marked-terminal` でターミナル向けにレンダリングする
- [ ] `chalk` でツール名、ファイルパス、エラーメッセージを色分けする
- [ ] diff 表示時にシンタックスハイライトを適用する

**優先度**: P1（重要）

#### E-04: API プロバイダ抽象化

**ユーザーストーリー**:
開発者として、将来 AWS Bedrock や Google Vertex AI 経由で Claude を利用するために、API 通信層を差し替え可能にしておきたい

**受け入れ条件**:
- [ ] `Provider` インターフェースを定義し、メッセージ送信・ストリーミングの共通契約を規定する
- [ ] Anthropic API 直接通信をデフォルトの `AnthropicProvider` として実装する
- [ ] Provider の切り替えを設定ファイルで行えるようにする
- [ ] メッセージ形式の変換ロジックは Provider 側に持たせる

**優先度**: P1（重要）

#### E-05: API 通信ログ

**ユーザーストーリー**:
セキュリティ管理者として、AI に送信されたデータを事後監査するために、全 API 通信のローカル記録機能が欲しい

**受け入れ条件**:
- [ ] `--debug` フラグで API リクエスト/レスポンスをローカルファイルに記録する
- [ ] ログファイルは `~/.claude-code-like/logs/` に日時付きで格納する
- [ ] API キーなどのセンシティブ情報はマスキングして記録する
- [ ] ログ出力はパフォーマンスに影響を与えない（非同期書き込み）

**優先度**: P1（重要）

## 非機能要件

### パフォーマンス
- Read / Glob / Grep: 各 500ms 以内（ファイル数 10,000 以下、ファイルサイズ 1MB 以下のプロジェクトを対象）
- Write / Edit: 各 500ms 以内（書き込みコンテンツ 1MB 以下、確認プロンプト待ちを除く）
- Bash ツール: タイムアウト 120 秒（設定で変更可能）
- ストリーミング表示: 最初のトークンが 2 秒以内に表示される（API レスポンス依存）

### ユーザビリティ
- 起動後すぐに入力可能（初期化処理 1 秒以内）
- ツール実行時に何をしているかを表示する（例: "Reading src/index.ts..."）（E2E テストの標準出力で確認）
- エラー時に原因と対処法を表示する（エラーハンドリングの表示文言は functional-design.md のエラーハンドリング表を参照）

### 信頼性
- ファイル書き込み前に確認プロンプトを表示し、意図しない変更を防ぐ
- API エラー（429 Rate Limit 等）時に適切なエラーメッセージを表示する
- 異常終了時に会話履歴が失われない（E-01 実装後に対応。MVP 段階ではプロセス終了シグナルをキャッチして保存を試みる）

### セキュリティ
- API キーは環境変数からのみ取得し、ファイルにハードコードしない
- Bash ツールは実行前に必ずユーザー確認を要求する
- ファイル操作はカレントディレクトリ配下に制限しない（本ツールはローカル開発者が自ら実行する CLI であり、Write/Bash の確認プロンプト必須により緩和する。詳細な根拠は architecture.md の入力検証セクションを参照）
- 通信先は Anthropic API エンドポイントのみ（仲介サービスを経由しない）
- 会話履歴・設定ファイルはローカルにのみ保存し、外部送信しない
- アプリケーションデータディレクトリ（`~/.claude-code-like/`）のパーミッションは `700`（所有者のみアクセス）に設定する
- テレメトリ・利用状況の外部送信は一切行わない
- `--debug` フラグで全 API 通信をローカルに記録でき、監査可能にする
- API 通信ログにはセンシティブ情報（API キー等）をマスキングする
- サブエージェントのツール使用はエージェント定義の `tools` フィールドで制限し、最小権限の原則を適用する

## 技術スタック（概要）

| カテゴリ | 技術 | 選定理由 |
|---------|------|----------|
| 言語 | TypeScript (strict mode) | 型安全性によるツール定義の明確化 |
| ランタイム | Node.js 22+ | ESM ネイティブ、追加依存なしの readline 対応 |
| AI SDK | @anthropic-ai/sdk | Claude API 公式 SDK、ストリーミング・Tool Use 対応 |
| テスト | Vitest | ESM ネイティブ、高速な単体テスト |
| ビルド | tsup | TypeScript バンドル、npm 公開向け |

主要技術のみを列挙しています。全ライブラリの詳細（chalk、marked、ora 等）は functional-design.md および architecture.md を参照してください。

## スコープ外

明示的にスコープ外とする項目:
- GUI / TUI フレームワーク（Ink 等は使わない。純粋な readline ベース）
- MCP（Model Context Protocol）連携
- 画像入力・動画入力などのマルチモーダル入力
- Web 検索機能
