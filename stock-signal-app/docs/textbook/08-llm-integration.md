# 第8章 LLM（Claude API）連携

## 学習目標

- 「LLM を使うべき所 / 使うべきでない所」を判断できる
- Claude API の基本呼び出しと、コスト見積もり・コスト制御ができる
- 「キー未設定でも壊れない」設計と、LLM 出力の検証可能性を実装できる

## facility-management との接続

初めての LLM 連携ですが、技術的には第3章（外部 API 連携）の応用です。違いは 2 つ: **有料**であること（1 呼び出しごとに課金）と、**出力が毎回変わる**こと（決定的でない）。この 2 つが設計判断のすべてを支配します。

## 本編

### 1. 最重要: どこに LLM を使うか（使わないか）

stock-signal-app の判断を一般化すると、こうなります。

| 処理 | LLM を使う? | 理由 |
|------|-----------|------|
| SMA・RSI の計算 | **使わない** | 数式で決まる。再現性・テスト可能性・無料を捨てる理由がない |
| 売買シグナル判定 | **使わない** | 「なぜ買いか」を説明できる必要がある。ルールなら根拠を表示できる |
| 年次報告書（英文 30 万字）から国別売上を抽出 | **使う** | 非構造化テキストの読解は数式にできない。LLM でしかできない仕事 |

原則: **決定的に解けるものは決定的に解く。LLM は「文章の理解」が必要な場所だけ**。そして LLM の出力は「下書き」に留め、最終判断（保存）は人間が行う——本アプリでは出典 URL を必ず付けて原文と照合できるようにしています。

### 2. SDK の基本形

```bash
npm install @anthropic-ai/sdk
```

```ts
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();  // ANTHROPIC_API_KEY 環境変数を自動で読む

const response = await client.messages.create({
  model: "claude-haiku-4-5",
  max_tokens: 1024,                    // 出力の上限（課金の上限でもある）
  system: "あなたは投資分析アシスタント。…（役割と規則）",
  messages: [{ role: "user", content: "…（処理対象のテキスト）" }],
});

// content はブロックの配列。text 型だけ集める
const text = response.content
  .filter((block) => block.type === "text")
  .map((block) => block.text)
  .join("\n");
```

モデルは用途と単価で選びます（2026-07 時点の入力/出力単価・100 万トークンあたり）:

| モデル | 単価（入/出） | 向き |
|--------|-------------|------|
| claude-haiku-4-5 | $1 / $5 | 抽出・分類など「読んで抜き出す」仕事。**本アプリの既定** |
| claude-sonnet-5 | $3 / $15 | バランス型 |
| claude-opus-4-8 | $5 / $25 | 複雑な推論 |

本アプリはモデル名を環境変数（`AI_MODEL`）にして、コードを変えずに差し替えられるようにしています。

### 3. コスト制御 — 「全文を投げない」が 9 割

LLM 料金はトークン量（≒文字量）に比例します。10-K 全文は 30〜60 万字 ≈ 10〜20 万トークン。毎回全文を投げると Haiku でも 1 回数十円になります。本アプリの対策は**抜粋戦略**です:

```
lib/ai/edgar.ts の流れ:
1. HTML → テキスト化（機械用メタデータ iXBRL を先に除去 ← 実際にゴミが混ざった実話あり）
2. キーワード（"china", "geographic", "segment"…）の周辺 ±750 字だけ切り出す
3. 重複区間をマージし、合計 2 万字（≈7,000 トークン）に制限
→ コストが 1/20 になり、しかも関係ない部分が減って抽出精度も上がる
```

これは RAG（検索してから渡す）の最小形です。**「LLM に渡す前に、プログラムで絞れるだけ絞る」**は LLM 連携の基本姿勢と覚えてください。1 回あたりのコストは `入力トークン × 入力単価 + max_tokens × 出力単価` で**実装前に**概算します（本アプリ: 約 1〜2 円/銘柄）。

### 4. プロンプト設計 — 「規則」で出力を縛る

出力が毎回変わる LLM を実用にするコツは、system プロンプトに**規則**を書くことです。本アプリの実物（要約）:

```
抽出対象: ① 国別・地域別の売上構成（特に中国。数値があれば%で）② 事業構成 ③ 地政学リスク
規則:
- 抜粋に書かれていることだけを使い、推測や一般知識で補わない   ← ハルシネーション対策
- 数値には「何の数値か」を短く添える                           ← 検証しやすくする
- 読み取れない項目は「抜粋からは不明」と書く                    ← 無理に埋めさせない
- 箇条書きで10行以内。前置きや結びの文は書かない                ← 後処理しやすくする
```

ポイントは「〜して」ではなく「**〜するな / できないときはこう言え**」を書くこと。特に「不明なら不明と書け」は、もっともらしい嘘（ハルシネーション）への一番簡単で効く対策です。

### 5. 「キー未設定でも壊れない」設計

有料機能は「設定した人だけ有効」にします。本アプリの実装パターン:

```ts
export function isAiConfigured(): boolean {
  return !!process.env.ANTHROPIC_API_KEY;
}
// Server Component → isAiConfigured() を props で渡す
// → 未設定ならボタンを disabled + 「設定すると使えます」の案内
// → Server Action 側でも二重にチェック（UI を迂回されても安全）
```

エラー処理は SDK の**型付き例外**で分岐し、利用者向けの日本語に変換します（`Anthropic.AuthenticationError` → 「API キーが無効です」、`RateLimitError` → 「しばらく待って再実行」。見本: `lib/ai/extract.ts` の `toFriendlyApiError`）。

### 6. 検証可能性 — AI の出力を信用しすぎない仕組み

本アプリの下書きには必ずフッターが付きます:

```
---
出典: 10-K（2026-02-25 提出） https://www.sec.gov/...
（AI 抽出の下書き。保存前に原文と照合すること）
```

「AI が言ったから」で終わらせず、**原文への経路を出力に埋め込む**。第4章で計算ロジックにテストを書いたのと同じで、LLM には「人間が検証できる形」という別種の安全網をかけます。
