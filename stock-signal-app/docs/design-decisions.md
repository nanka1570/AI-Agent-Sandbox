# 設計判断の記録

このアプリを作るときに調査・検討して決めたことと、その理由の記録。将来「なぜこうなっているのか」「変更してよいのか」を判断するために残す。

## 前提

- 個人用のローカルツール（公開・マルチユーザー化はスコープ外）
- 「売買タイミング（いつ）はテクニカル指標、銘柄の健全性（何を）はファンダメンタルズ」という役割分担

## 判断一覧

### DB は SQLite（Supabase 等の外部 DB を使わない）

- 個人用ローカルツールなので、外部サービスに依存すると「サービス側の一時停止でアプリが動かない」リスクだけが増える（実際に別プロジェクトで Supabase の一時停止により作業がブロックされた経験がある）
- 変更する場合: Prisma を使っているため、`prisma/schema.prisma` の datasource と `lib/prisma.ts` のアダプタを差し替えれば PostgreSQL 等へ移行できる

### データ取得は yahoo-finance2（非公式 API）

- 無料・API キー不要で、日足 OHLCV（`chart()`）とファンダメンタルズ（`quoteSummary()`）の両方が取れる唯一の現実的な選択肢だった（2026-07 時点）
- 非公式のため**いつか壊れる前提**で、依存は `lib/data/` に隔離してある。壊れたときの対処は [maintenance.md](./maintenance.md) を参照

### 価格は全面的に adjClose（調整後終値）を使う

- 生の終値（close）は株式分割で不連続になる（例: NVIDIA は 2024 年に 1→10 分割）。生値で SMA を計算すると分割日をまたいだ平均が大きく歪み、**存在しないクロスシグナルが出る**
- チャート表示だけ生値にすると、同じチャート上で価格線と SMA 線が乖離して見えるため、表示も含めて調整後に統一（Yahoo Finance のチャートと同じ流儀）

### ファンダメンタルズは「現在値」のみ・バックテストはテクニカルのみ

- 過去の PER・EPS の履歴データは無料 API では取得できない（有料プランが必要）と調査で判明
- そのため「過去のファンダでバックテスト」は諦め、ファンダは現在値による銘柄スクリーニング（5点満点スコア）に役割を限定した
- **将来「過去ファンダでバックテストしたい」となったら**: Financial Modeling Prep 等の有料プランが必要。この調査をやり直さないこと

### データ同期は「1 リクエスト = 1 銘柄」

- 101 銘柄 × 5 年分を 1 つの API Route で処理すると数分かかり、タイムアウトし、進捗も返せない
- クライアントが銘柄リストを直列に fetch する方式なら、完了数がそのまま進捗表示になり、失敗した銘柄だけ再実行できる
- DB の最終日は「取引時間中の途中値」の可能性があるため、同期のたびにその日を含めて取り直す（`lib/data/sync.ts`）

### NASDAQ-100 の銘柄リストは静的ファイル

- 構成変更は年数回しかないため、API で動的取得するのは過剰と判断
- `lib/constants/nasdaq100.ts` に手動更新（手順は [maintenance.md](./maintenance.md)）

### ライト/ダーク両対応（ブラウザ設定に追従）

- ブラウザの配色設定に追従する（`app/globals.css` の `color-scheme: light dark`）
- ダークモードの色は各コンポーネントの Tailwind `dark:` 変種で定義している。**新しい UI を追加するときは `dark:` の配色も必ずセットで指定する**こと（付け忘れると create-next-app 初期状態と同じ「白いカードにほぼ白の文字」問題が再発する）
- チャート（Recharts）の軸・グリッドは `currentColor` で描画し、外側の div の文字色クラスで両モードに対応している

### バックテストは簡易モデル

意図的に以下を簡略化している。結果は実際より楽観的になる（UI に注記済み）:

- 約定はシグナル**当日の調整後終値**（実際には翌日以降にしか売買できない）
- 全額買い / 全額売りのみ（分割売買・部分利確なし）
- 手数料・スリッページ・税は考慮しない
- **期間開始前に発生したクロスは拾わない**: 例えば上昇トレンド継続中の銘柄で期間を区切ると、ゴールデンクロスが期間より前にあるため「期間中は一度も買わない」結果になる

## シグナル仕様

### SMA クロス（`lib/signals/evaluate.ts` の `evaluateSmaCross`）

- **ゴールデンクロス**（買い）: SMA50 が SMA200 を上抜けた日
- **デッドクロス**（売り）: SMA50 が SMA200 を下抜けた日
- 判定には最低 **201 営業日**のデータが必要。足りない銘柄はダッシュボードに「データ不足」と表示

### RSI（`evaluateRsi`）

- 期間 14 日、Wilder 方式の平滑化（`lib/indicators/rsi.ts`）
- **買い**: RSI が 30 以下の圏に**入った瞬間**（売られすぎ）
- **売り**: RSI が 70 以上の圏に**入った瞬間**（買われすぎ）
- 圏内に留まっている間はシグナルを連発しない

### 「現在シグナル」（ダッシュボードの表示）

- 直近 **5 営業日以内**に発生したシグナルを表示。なければ「中立」
- 2 つのルールは統合せず、独立した列で表示（矛盾したときにどちらを信じるかは利用者の判断）

### ファンダスコア（`lib/fundamentals/score.ts`、5点満点）

| # | 条件 | 意図 |
|---|------|------|
| 1 | PER が 0〜35 | 赤字（マイナス）と過熱（高すぎ）を除外 |
| 2 | PEG が 0〜2 | 成長率と比べて割高でない |
| 3 | 収益成長率 > 10% | 成長している |
| 4 | 利益率 > 15% | 稼ぐ力がある |
| 5 | 予想 PER < 実績 PER | 利益が改善する見込み |

閾値は一般的な目安。取得できない指標は 0 点扱い（詳細ページで「取得不能」と表示）。

## 用語メモ

- **SMA（単純移動平均）**: 直近 N 日の終値の平均。株価のノイズをならしてトレンドを見る
- **ゴールデンクロス / デッドクロス**: 短期の平均線が長期の平均線を上抜け / 下抜けすること。トレンド転換のサインとされる
- **RSI**: 直近の値動きのうち上昇が占める割合（0〜100）。低いほど売られすぎ、高いほど買われすぎ
- **PER**: 株価が 1 株あたり利益の何倍か。低いほど割安（ただし赤字だとマイナスになり意味が変わる）
- **PEG**: PER ÷ 利益成長率。成長株の割高・割安を測る
- **最大ドローダウン**: 期間中の資産のピークからの最大下落率
- **Buy & Hold**: 期間初日に買って最終日まで持ち続ける戦略。バックテストの比較基準
