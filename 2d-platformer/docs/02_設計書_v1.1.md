## 3. ゲームループ設計

### 3.1 固定タイムステップ方式

物理演算やゲームロジックの一貫性を保つため、固定タイムステップを採用する。

```
1フレーム = 1/60秒 (約16.67ms)

ループ:
  1. 経過時間を蓄積
  2. 蓄積時間 >= 1フレーム分 の間:
     - handleInput()   // 入力処理
     - update(dt)      // ゲームロジック更新（dt = 固定値）
     - 蓄積時間 -= 1フレーム分
  3. render()           // 描画（毎ループ1回）
```

**選定理由：** 可変タイムステップはジャンプの高さや移動速度がフレームレートに依存してしまう。プラットフォーマーでは物理の再現性が重要なため、固定タイムステップが適している。

### 3.2 Game クラスの責務

- SFMLウィンドウの生成・管理
- ゲームループの実行
- 現在のシーンへの処理委譲（handleInput → update → render）
- シーン遷移の管理

### 6.3 内部解像度とスケーリング

```
内部解像度:  640 x 360 ピクセル（16:9、32pxタイルが横20枚）
表示解像度:  1280 x 720 ピクセル（2倍スケーリング）

方法: sf::View を使い、内部解像度サイズのビューを設定
      → SFMLがウィンドウサイズに合わせて自動スケーリング
      → デフォルメキャラの滑らかなスケーリングが実現できる
```

**補足：** デフォルメスタイルはドット絵より高解像度のスプライトを使用するため、内部解像度を640x360に設定。32pxタイルによりキャラクターの表現力が広がる。

## 7. 当たり判定

### 7.1 方式：AABB（軸平行バウンディングボックス）

**選定理由：** タイルベースの2DプラットフォーマーにはAABBが最もシンプルで十分。ピクセル単位は処理コストが高く、今回は不要。

### 7.2 衝突判定の流れ

```
1. エンティティの移動後の位置を仮計算
2. X軸方向の衝突チェック → 衝突があれば位置補正
3. Y軸方向の衝突チェック → 衝突があれば位置補正
4. 接地判定の更新（isOnGround）
```

**XとYを分離して判定する理由：** 同時に判定すると、壁に沿って落下する際にめり込みや引っかかりが発生する。分離することで自然な挙動になる。

### 7.3 Collision ユーティリティ

```cpp
namespace Collision {
    // AABB同士の重なり判定
    bool intersects(const sf::FloatRect& a, const sf::FloatRect& b);

    // エンティティ vs タイルマップ の衝突解決
    void resolveMapCollision(Entity& entity, const TileMap& map, float dt);

    // エンティティ vs エンティティ（攻撃判定等）
    bool checkEntityCollision(const Entity& a, const Entity& b);
}
```

## 11. アニメーション

```cpp
class Animation {

    sf::Texture* texture;

    float frameDuration;              // 1フレームあたりの秒数
```

## 14. エラーハンドリング方針

| 状況 | 対応 |
|------|------|
| リソース読み込み失敗 | エラーログ出力 + 代替表示（マゼンタ色の四角等）で続行 |
| マップファイル破損 | エラーログ + タイトルに戻す |
| 想定外の状態遷移 | assert で検出（デバッグビルド時） |
| FPS低下 | 固定タイムステップにより論理的な影響なし。描画スキップは行わない |

## 15. AI開発ツール設定

### 15.1 CLAUDE.md（Claude Code用）

```markdown
# プロジェクトルール

## 技術スタック
- C++17 / SFML 2.6 / CMake
- ビルド: mkdir build && cd build && cmake .. && make

## コーディング規約
- クラス名: PascalCase（Player, TileMap）
- メソッド名: camelCase（handleInput, update）
- メンバ変数: camelCase（moveSpeed, currentState）
- 定数: UPPER_SNAKE_CASE（MAX_HP, TILE_SIZE）
- ヘッダーガード: #pragma once
- インクルード順: 標準ライブラリ → SFML → プロジェクト内

## 設計方針
- Entity基底クラスを継承してPlayer/Enemyを実装
- シーン管理はScene基底クラスのポリモーフィズム
```
