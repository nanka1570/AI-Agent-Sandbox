| プロジェクト名 | 2Dファンタジープラットフォーマー（仮） |
| 作成日 | 2026年2月14日 |
| バージョン | 1.3 |
| ステータス | 要件定義フェーズ |

---

## 1. プロジェクト概要

### 1.1 目的

C++の技術学習を目的とした2Dプラットフォーマーゲームの開発。完成後は個人で遊べるゲームとして公開することを想定。

### 1.2 ターゲットユーザー

- デフォルメキャラクターのゲームが好きなカジュアルゲーマー
- 2Dアクションプラットフォーマーファン

### 1.3 スコープ（MVP）

MVP（最小限の製品）として、3ステージ構成のプレイ可能なゲームを完成させる。

### 1.4 制約条件

| 項目 | 内容 |
|------|------|
| 開発期限 | なし（個人開発） |
| 開発人数 | 1人 |
| 開発可能時間 | 平日1時間、休日3〜4時間 |

---

## 2. 開発環境・ツール

### 2.1 技術スタック

| 項目 | 選定 | 理由 |
|------|------|------|
| 言語 | C++17 | 業務とのスキル相乗効果 |
| 2Dライブラリ | SFML 2.6 | C++らしいOOP設計、学習向き |
| ビルド | CMake | SFML公式推奨、クロスプラットフォーム |
| バージョン管理 | Git / GitHub | ソース公開・履歴管理 |
| グラフィック | デフォルメ（2D イラスト） | 親しみやすいキャラクター表現 |
| プラットフォーム | Windows（PC） | メインターゲット |
| 操作方法 | キーボードのみ | MVPではゲームパッド非対応 |

### 2.2 AI開発ツール体制

本プロジェクトでは複数のAIツールを使い分けて開発を進める。各ツールの役割分担は以下の通り。

| ツール | 役割 | 用途 |
|------|------|------|
| Claude Code（Opus 4.6） | **メイン開発エージェント** | ターミナルベースでのコア実装、リファクタリング、テスト |
| Claude Opus 4.6（チャット） | **設計・相談役** | アーキテクチャ設計判断、コードレビュー、技術的な相談 |
| Google Antigravity（Gemini 3 Pro） | **デザイン担当** | 画面デザイン、デフォルメキャラの方向性検討、ビジュアル面の設計 |
| OpenAI Codex | **サブ開発** | コード生成補助、ルーチン的な実装の支援 |

**運用方針：**

- 設計の大きな判断はOpus 4.6（チャット）で行い、一貫性を保つ
- 実装作業はClaude Code（Opus 4.6）をメインエージェントとして進める
- Antigravity上での開発時はPlanningモードを使用（複雑なタスク向け、計画→承認→実行の流れ）
- 各AIツールにこの要件定義書を読み込ませ、コンテキストを共有する
- プロジェクトルールの統一にはgemini.md（Antigravity）、CLAUDE.md（Claude Code）等を活用する

## 3. 機能要件

### 3.1 機能一覧（優先度付き）

**Must（MVP必須）：**

| 機能 | 説明 |
|------|------|
| プレイヤー移動 | 左右移動・ジャンプ |
| 攻撃アクション | 剣攻撃または魔法攻撃 |
| ダッシュ | 短距離の素早い移動（クールダウン付き） |
| 壁ジャンプ | 壁に張り付いてジャンプ |
| 敵キャラクター | 基本的なAIで動く敵 |
| ステージクリア判定 | ゴール地点到達でクリア |
| タイトル画面 | ゲーム開始・終了のUI |
| ステージ選択 | 3ステージから選択 |
| HPシステム | プレイヤーの体力管理 |

**Should（あると良い）：**

| 機能 | 説明 |
|------|------|
| BGM・SE | ステージBGMと効果音 |
| ボス戦 | ステージ最後のボス戦 |
| アニメーション | プレイヤー・敵のデフォルメアニメ |

**Could（将来的な拡張）：**

| 機能 | 説明 |
|------|------|
| ゲームパッド対応 | 将来的な拡張 |
| スコア・ランキング | クリアタイム等の記録 |

### 3.2 ゲームフロー

```
タイトル画面 → ステージ選択 → ゲームプレイ → クリア or ゲームオーバー → リザルト → ステージ選択に戻る
```

### 3.3 ステージ構成（MVP）

| ステージ | テーマ | 特徴 | 難易度 |
|----------|--------|------|--------|
| 1 | 森の入口 | チュートリアル的なステージ | ★☆☆（簡単） |
| 2 | 古城 | 壁ジャンプを活用する縦構成 | ★★☆（普通） |
| 3 | 魔王の塔 | 全アクションを使う総合ステージ | ★★★（難しい） |

### 3.4 操作体系

| キー | アクション | 備考 |
|------|-----------|------|
| ← / → or A / D | 左右移動 | |
| Space | ジャンプ | 壁接触時は壁ジャンプ |
| Z or J | 攻撃（剣） | |
| X or K | 魔法攻撃 | MP消費等は設計フェーズで決定 |
| Shift or L | ダッシュ | クールダウン付き |
| Esc | ポーズ / メニュー | |

## 6. 設計フェーズで決定すべき事項

以下の項目は要件定義フェーズでは未決定とし、設計フェーズで詳細を決める。

### 6.1 基本設計

- ディレクトリ構成
- クラス設計（プレイヤー・敵・マップ等のクラス階層）
- ゲームループ設計（固定タイムステップ vs 可変）
- シーン管理（タイトル・ゲームプレイ・リザルトの遷移）
- 当たり判定の方式（AABB、ピクセル単位等）
- マップデータ形式（タイルマップエディタの選定含む）

### 6.2 詳細設計

- 各クラスのメンバ変数・メソッド一覧
- 状態管理（プレイヤーの状態遷移：待機・走行・ジャンプ・攻撃・ダッシュ等）
- 敵AIの行動パターン
- ダメージ計算・無敵時間等のパラメータ
- エラーハンドリング方針
- リソース管理（画像・音声の読み込み・管理方法）

### 6.3 UI/UX設計

- 画面レイアウト（HUDの位置、HPバーのデザイン等）
- メニュー画面のワイヤーフレーム
- カメラワーク（プレイヤー追従の方法）

### 6.4 AI開発ツール設定

- Antigravity: gemini.mdに登録するコーディング規約・プロジェクトルール
- Claude Code: CLAUDE.mdに登録するプロジェクトルール
- エージェントに任せるタスクの粒度定義
- 人間レビューのチェックポイント設定
- 各AIツール間のコンテキスト共有方法（共通ドキュメント形式等）
